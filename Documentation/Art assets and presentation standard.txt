ART ASSETS AND PRESENTATION STANDARD
Besieged in Constantinople — 4 November 2026

Purpose
Create artwork that fits the existing PC interface with minimal per-image adjustment. Keep the established painterly Byzantine realism, warm gold light and deep blue shadows. Preserve working systems: EventCardArt and Content/EventArtwork.json remain the event-art authority. This is an authoring and verification agreement, not a new renderer or a requirement to regenerate existing art.

Event illustrations
Preferred master: 2048 x 1152 pixels (16:9), opaque lossless PNG in sRGB. A larger clean source can be retained outside runtime Resources; use a 2048-pixel long edge for the usual runtime image. Existing 1672 x 941 and 3:2 images remain valid. If generation tools cannot output exact dimensions, accept the nearest useful composition and use contain; never stretch or crop just to satisfy the suggested size.
Keep faces, hands and the key story action roughly 8% away from all image edges. Allow expendable scenery around the subject. No baked captions, UI, decorative border, watermark or tiny lettering. This safe zone is a composition guide, not additional transparent padding. Leave the interface to draw its own goldwork.
Default fit is contain: show the entire picture inside an 8-UI-unit inset, clipped viewport. Natural navy margins are preferable to cropped heads or distorted bodies. Use cover only for deliberately crop-tolerant scenery; set focusY in the manifest, inspect the resulting crop and preserve the full image in the enlarged view. The renderer preserves aspect ratio and places the frame outside the clipping mask. Do not add a second aspect-ratio fitter or independent clipping component to event instances.
Keep the existing event composition: a substantial illustration above the narrative on the left, choices on the right. The normal art panel is approximately 43% of event width and 46% of its height; taller source art uses that height, wide art uses its width. Enlarging shows the whole illustration. Do not impose identical image area on every aspect ratio or enlarge images by taking away readable choices.

Prompt template
[Event ID / scene / named characters / action / time of day]. Historical-fiction illustration of Constantinople around 1452-1453, matching the supplied palace and event-art references. Painterly realism, coherent anatomy and fabric, atmospheric depth, warm gold and restrained navy. Landscape 16:9; principal action readable at thumbnail size; important faces and hands inside the central 84% of the canvas. No text, UI, border or watermark. Deliver one clean opaque image. Record any intentional historical reconstruction or fictional detail in the handover, not on the image.

Icons and flags
UI icons: usually 512 x 512 transparent PNG masters, centred with consistent visual weight and 10-15% clear edge padding. Review at actual 24, 32, 48 and 64-pixel display sizes. Use one clear silhouette, restrained gold highlights and enough contrast on navy; avoid tiny detail as the only identifier. Keep a text label or tooltip; colour alone must not communicate state. Status meaning, not decorative variation, determines icon choice.
Flags: usually 768 x 512 or 512 x 512 source canvases, retaining the actual emblem/flag proportions with transparent margins as needed. Display with preserveAspect. Do not distort historical designs into a shared aspect ratio. Provenance and reconstruction notes belong in the asset handover. Keep one stable court ID for its territories.

Characters, units and animation
Court figures: full-body transparent PNG, typically 1024 x 1536; allow varied widths without stretching. Include the complete head, hands, clothing and feet, with modest clear edge space. Floor position is the shared alignment reference. Match relative human scale and ground contact in the scene; do not bake nameplates, button frames or scene backgrounds into the figure.
Small battlefield units: target approximately 256-512 pixels in height per individual master, then judge at actual on-screen size. For animation sheets keep cell dimensions, pose scale and foot pivot consistent; add transparent gutters (at least 4 pixels per cell) and record the grid, frame order, timing and pivot. Effects are separate reusable sprites or particles. Do not deliver GIF as the runtime animation format. Do not invent animation infrastructure for static art.
Background scenes: prefer 2560 x 1440 for new full-screen scenes; 1920 x 1080 is acceptable. Compose across the whole canvas, with critical landmarks away from crop edges and known UI-covered areas. Ultrawide screens reveal or crop scenery according to that screen's established policy; never stretch people or architecture.

Import and memory
Use the existing local importer/pipeline as the first reference. Event covers currently use Texture2D/RawImage, no mipmaps, bilinear filtering and uncompressed desktop textures capped at 2048; keep those settings unless a measured quality or memory issue justifies change. UI icons/character cutouts need correct transparency and appropriate Sprite import where their consumer expects Sprite. Do not mark textures Read/Write enabled without a real CPU-reading use. Mipmaps can help heavily minified/zoomable world assets but cost memory; decide per consumer, not globally.
PNG file size is not GPU memory usage: an uncompressed 2048 x 1152 RGBA texture is about 9 MiB before mipmaps. Keep the existing event-art cache and live-view ownership; do not preload the entire catalogue. Avoid automatic 4K copies of every asset or blanket no-compression policies for all asset types. Use lossless masters; choose final compression from actual close-up and in-game quality checks.

Integration and acceptance
Add or replace an image under its stable Resources path, preserve existing .meta GUIDs when replacing, and update the existing Content/EventArtwork.json mapping. Each event mapping identifies node, path, source, fit and focusY. A generated image on disk is staged, not integrated. Record origin, filename, dimensions and any reconstruction caveat. No hidden gameplay consequences in asset metadata or captions.
Run Tools/validate_event_art.py before build: it checks IDs, paths, fit modes, focus range, source metadata and PNG headers. It reports unusual sizes/aspects for review without rejecting valid legacy art. For visible edits use the opt-in -event-frame-capture player check: isolated saves, real renderer, all current mappings, contain/cover/fallback, resize, clipping, enlargement, Close/Back and unchanged campaign state.
PC layout reference is the existing canvas scaling, not a physical pixel promise. Minimum practical target: 1280 x 720. Review 1600 x 900 and 1920 x 1080; additionally check 16:10 (1920 x 1200), 4:3 (1280 x 960) and 21:9 (2560 x 1080) when changing shared art layout. These are test targets, not a claim that every game screen has been certified. At 1440p/4K, UI layout scales but source detail does not magically increase: inspect enlargement when higher-resolution assets are proposed. Test Windows display scaling separately before declaring general DPI support.
Use normal screenshots and enlarged views to confirm no gold-border bleed, cut heads, stretched art, alpha fringe, crushed dark detail, unreadable icons or blocked buttons. Borders and masks must remain correct after a live resize, not merely on first open. Keep click targets independent of transparent decorative pixels where appropriate. No new mobile layout is required.

Lead-agent workflow
Search the manifest and existing asset names first. Reuse verified artwork before generating more. Agree on composition and a single representative preview before commissioning a large batch. Give each asset a stable ID, owner and acceptance state: staged, integrated, compiled, visually checked, published. One owner per shared source section and one Unity build slot; stage incomplete work outside Assets. Apply local fixes instead of replacing the rendering framework. Measure memory or loading stalls before adopting atlases, Addressables or a new rendering stack. A good specification prevents rework; a giant framework can become rework wearing a crown.
